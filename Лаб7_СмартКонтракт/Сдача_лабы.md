# Как сдавать лабораторную работу 7

Сдача занимает 10–15 минут. Порядок показа повторяет методичку: образец `StudentRegistry`, вариант 1 (книги), вариант 2 (сотрудники), собственная функция. В каждом пункте указано, что нажать, что ввести, что должно получиться и что сказать.

Значения в таблицах проверены в Remix и совпадают с рисунками в отчете. Не прогонялись только необязательные демонстрации наследников `ExtendedBookRegistry` и `ExtendedEmployeeRegistry` (они помечены «если попросят»).

## 0. Подготовка (до подхода к преподавателю)

1. Открыть <https://remix.ethereum.org>. Если файлов нет, кнопкой **+ Create new file** создать `StudentRegistry.sol`, `BookRegistry.sol`, `EmployeeRegistry.sol` и вставить в них код из папки `D:\Unik\SSP\Лаб7_СмартКонтракт`.
2. Открыть файл нужного раздела → вкладка **Solidity Compiler** → версия **0.8.19** → **Compile**. Должна появиться зеленая галочка и надпись **Compiled**. Компилировать нужно тот файл, контракт из которого будете разворачивать: для разделов 1 и 4 – `StudentRegistry.sol`, для раздела 2 – `BookRegistry.sol`, для раздела 3 – `EmployeeRegistry.sol`.
3. Вкладка **Deploy & Run Transactions** → Environment **Remix VM**.

**Сказать:** «Как в методичке, каждый контракт в своем файле: образец и своя функция – в `StudentRegistry.sol`, вариант 1 – в `BookRegistry.sol`, вариант 2 – в `EmployeeRegistry.sol`. Контракты вариантов написаны по образцу, с теми же разделами кода. Работаю в Remix IDE, как в методичке, в эмуляторе Remix VM: он дает 100 тестовых ETH на газ, настоящие деньги не тратятся».

Как работать с контрактом:

- Строки вводятся в поле как есть, например `City Library`. Если параметров несколько, их можно ввести одной строкой через запятую, строки в кавычках: `"War and Peace", "L. Tolstoy", 1869, true, "Novel"`.
- **Оранжевые** кнопки (transact) меняют данные и создают транзакцию.
- **Синие** кнопки (call) только читают данные, транзакции нет, газ не тратится.
- Результат call появляется под кнопкой. Ошибки и транзакции видны в терминале внизу.
- После обновления страницы развернутые контракты исчезают. Нужно снова нажать Deploy, код при этом сохраняется.

**Сказать:** «Кроме добавления, изменения и увольнения контракт считает фонд оплаты труда и средний оклад и ищет сотрудников по должности и стажу. В Solidity нет дробных чисел, поэтому средний оклад 10000 / 3 = 3333: дробная часть отбрасывается. При пустом списке функция возвращает 0, чтобы не делить на ноль. | Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Contract: `StudentRegistryPlus`, параметры `"My University", "IT"` → **Deploy** | Контракт развернут |
| 2 | `registerStudent` четыре раза: `"Anna", 20, "Computer Science"`; `"Boris", 21, "Mathematics"`; `"Clara", 22, "Computer Science"`; `"Dmitry", 23, "Computer Science"` | Четыре транзакции |
| 3 | `getStudentsByMajor`: `Computer Science` | `[1, 3, 4]` |
| 4 | `getStudentsByMajor`: `Mathematics`; затем `Biology` | `[2]`; пустой массив |

| 6 | `getStudentWithMajor`: `1, "Computer Science"`; `department` | `true`; `IT`: унаследованные функции работают |

**Объяснение функции (главное на сдаче):**

1. Функция возвращает номера всех действующих студентов заданной специальности.
2. Она объявлена `public view`: вызывается снаружи и только читает данные. Поэтому в Remix это синяя кнопка call, транзакции нет и газ не тратится.
3. Строки в Solidity нельзя сравнить через `==`. Строка переводится в байты (`bytes`), от них берется хэш `keccak256`. Одинаковые строки дают одинаковые хэши, поэтому сравниваются хэши. Хэш искомой специальности считается один раз и хранится в `wanted`.
4. Первый цикл по номерам от 1 до `studentCount` считает подходящих: студент активен и хэш его специальности равен `wanted`. Подсчет нужен, потому что длина массива в памяти задается при создании и потом не меняется.
5. Второй цикл создает массив `ids` нужной длины и записывает в него номера подходящих студентов. Переменная `index` указывает, куда писать следующий номер.
6. Ограничения: сравнение чувствительно к регистру (`computer science` не найдет `Computer Science`). Цикл идет по всем студентам, поэтому вызов из транзакции при большом списке был бы дорогим по газу.
7. Функция добавлена в наследник `StudentRegistryPlus`, поэтому код методички не менялся.

## 6. Частые вопросы преподавателя

| Вопрос | Короткий ответ |
|---|---|
| Чем Transact отличается от Call? | Transact меняет состояние и создает транзакцию с оплатой газа, Call только читает данные функцией `view` бесплатно |
| Зачем `require`? | Проверяет условие: при нарушении транзакция отменяется, все изменения откатываются, в терминале видна причина |
| Что делает `onlyAdmin`? | Проверяет `msg.sender == admin` перед телом функции, изменять данные может только развернувший контракт аккаунт |
| Зачем `mapping`? | Хранит записи по ключу: `books[id]` сразу возвращает книгу без перебора |
| Почему удаление мягкое? | Запись не стирается, а помечается флагом, номера остальных записей не сдвигаются |
| Что такое газ? | Плата за операции, меняющие состояние. Поэтому в контракты не переносят тяжелые вычисления и бесконечные циклы |
| Почему сравнение строк через `keccak256`? | Оператор `==` не работает для строк, а одинаковые строки дают одинаковые хэши |
| Что дает наследование? | Наследник получает поля и функции родителя и добавляет свои без изменения исходного кода |
| Почему пропадают контракты после обновления страницы? | Remix VM – эмулятор в памяти браузера, он не сохраняет состояние |
