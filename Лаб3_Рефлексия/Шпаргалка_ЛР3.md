# Шпаргалка к ЛР 3 «Рефлексия в C#»

Программа: `laba3/laba3/Program.cs`, .NET 10. Пространство имён `LabReflection`. `Main` по очереди вызывает `Task1AndTask2`, `Task3`, `Task4AndTask5`, `Task6`, `Task7`.

## 1. Главная идея в двух предложениях

**Рефлексия (Reflection)** — это получение информации о типах во время выполнения программы и работа с ними без знания типа на этапе компиляции: узнать поля, методы, свойства, конструкторы, создать объект, вызвать метод, прочитать или изменить поле, в том числе приватное.

Это возможно, потому что сборка .NET хранит рядом с IL-кодом **метаданные**: описание всех типов и их членов. Рефлексия читает эти метаданные через классы пространства имён `System.Reflection`.

## 3. Разбор по заданиям

### Задание 1. Класс с приватными полями

**Что в коде.** `ReflectionTarget` хранит данные в приватных полях, а наружу открывает свойства с проверкой значений:

- `Age`: отрицательное значение заменяется на 0;
- `Name`: пустая строка или пробелы заменяются на `"Unknown"`;
- `Rating`: значение обрезается до диапазона 0–5 через `Math.Clamp`.

**Что происходит.** Создаётся объект `new ReflectionTarget(-5, "", 7.5)`. Конструктор пишет не в поля, а в свойства, поэтому срабатывают проверки.

**Вывод:** `Unknown, возраст: 0, рейтинг: 5`.

**Смысл:** это обычная **инкапсуляция** — поля скрыты, доступ только через свойства с проверкой. В заданиях 4–6 её обходят рефлексией.

### Задание 2. Инспекция методов

**Шаги:**
1. `Type type = typeof(ReflectionTarget);` — получаем объект `Type`, описание класса.
2. `type.GetMethods()` без параметров возвращает только **публичные** методы экземпляра и статические, включая унаследованные от `object`: **11** штук.
3. `type.GetMethods(BindingFlags.Public | BindingFlags.NonPublic | BindingFlags.Instance | BindingFlags.Static)` возвращает **все** методы: **15** штук.
4. Методы с именами `get_...` и `set_...` отбрасываются. Это аксессоры свойств: компилятор превращает свойство `Age` в методы `get_Age` и `set_Age`.
5. Для каждого метода печатается уровень доступа (`IsPublic`, `IsPrivate`, `IsFamily` — protected), `static`, тип результата `ReturnType` и параметры `GetParameters()`.

**Почему 11 и 15:**
- 11 публичных = `GetDescription` + 6 аксессоров (`get/set` для `Age`, `Name`, `Rating`) + 4 метода `object` (`GetType`, `ToString`, `Equals`, `GetHashCode`);
- 15 всех = 11 + `IsAdult` + `GetClassMarker` + `MemberwiseClone` + `Finalize` (последние два у `object` защищённые).

**Вывод программы:**
```
public String GetDescription()
private Boolean IsAdult()
private static String GetClassMarker()
public Type GetType()
other Object MemberwiseClone()     ← protected internal, поэтому «other»
protected Void Finalize()
public String ToString()
public Boolean Equals(Object obj)
public Int32 GetHashCode()
```

`MemberwiseClone` выводится как `other`, потому что он `protected internal`: `IsFamily` для него ложно, верно `IsFamilyOrAssembly`.

### Задание 3. Динамическое создание объектов

**Без параметров:**
1. `Activator.CreateInstance(targetType)` создаёт объект без `new`, вызывая конструктор без параметров. Возвращает `object`.
2. `targetType.GetProperty("Name")` даёт `PropertyInfo`.
3. `nameProperty.SetValue(target, "Reflection object")` записывает значение. Вызывается сеттер, поэтому проверка тоже работает.

Результат: `Reflection object, возраст: 25, рейтинг: 4,8`.

**С параметрами:**
1. `GetConstructor(new[] { typeof(int), typeof(string), typeof(double) })` ищет конструктор с точно такими типами параметров.
2. `constructor.Invoke(new object[] { 30, "Dynamic object", 4.5 })` вызывает его.

Результат: `Dynamic object, возраст: 30, рейтинг: 4,5`.

Аргументы передаются как `object[]`: значения `int` и `double` при этом **упаковываются** (boxing).

### Задания 4–5. Приватное поле

**Шаги:**
1. Создаётся `new SecretCalculator(10)`. Снаружи значение `_secretValue` можно только прочитать через `ReadValue()`, изменить нельзя.
2. `type.GetField("_secretValue", BindingFlags.NonPublic | BindingFlags.Instance)` находит приватное поле. Без флага `NonPublic` вернулся бы `null`.
3. `secretField.SetValue(calculator, 25)` записывает в поле 25.
4. `ReadValue()` теперь возвращает 25.

**Вывод:** `До: 10`, `После: 25`.

**Обработка ошибок:**
- `MissingFieldException` — поле не найдено (программа сама бросает его, если `GetField` вернул `null`);
- `FieldAccessException` — нет прав на доступ к полю.

**Смысл:** рефлексия **обходит инкапсуляцию**. Модификатор `private` защищает от ошибок при компиляции, но не от доступа во время выполнения.

### Задание 6. Приватные методы и делегаты

**Через `Invoke`:**
1. `new SecretCalculator(5)`.
2. `GetMethod("Calculate", BindingFlags.NonPublic | BindingFlags.Instance)` находит приватный метод.
3. `Invoke(calculator, new object[] { 3, 4 })` вызывает его: `(5 + 3) * 4 = 32`.
4. Так же вызывается `Reset` без параметров (`Invoke(calculator, null)`), после чего `ReadValue()` возвращает 0.

**Через делегат:**
1. Создаётся `new SecretCalculator(7)`.
2. `CreateDelegate(typeof(Func<int, int, int>), secondCalculator)` превращает `MethodInfo` в обычный делегат, привязанный к этому объекту.
3. `calculateDelegate(2, 3)` = `(7 + 2) * 3 = 27`.

**Зачем делегат:** `Invoke` каждый раз проверяет аргументы и упаковывает их в `object[]`, это медленно. Делегат создаётся один раз и потом вызывается почти как обычный метод. Это стандартный способ ускорить многократные вызовы через рефлексию.

### Задание 7. Система плагинов

**Устройство:**
- `IPlugin` — контракт: `Name`, `Version`, `Execute()`.
- `IParameterizedPlugin : IPlugin` — плюс `ExecuteWithParams(Dictionary<string, object>)`.
- `[Plugin("Calculator")]` на классе и `[PluginMethod("...")]` на методах — свои атрибуты, метаданные для описания плагинов.

**Работа `PluginManager`:**
1. **Конструктор** создаёт каталог `Plugins` рядом с exe, если его нет.
2. **`LoadPlugins()`** берёт все `*.dll` из `Plugins`, для каждой вызывает `Assembly.LoadFrom(path)` и `assembly.GetTypes()`. Ошибка одной DLL не останавливает остальные (`try-catch`). В нашем запуске каталог пуст.
3. **`LoadConfiguredPlugins()`** читает `plugins.config` (две строки: `LabReflection.CalculatorPlugin`, `LabReflection.LoggerPlugin`) и выбирает из текущей сборки типы с такими полными именами.
4. **`LoadPluginTypes()`** проверяет каждый тип:
   - есть атрибут `PluginAttribute` (`GetCustomAttribute<PluginAttribute>()`);
   - тип реализует `IPlugin` (`typeof(IPlugin).IsAssignableFrom(type)`);
   - это не интерфейс и не абстрактный класс (такой нельзя создать);
   - такой плагин ещё не загружен.

   Затем `Activator.CreateInstance(type)` создаёт объект, он приводится к `IPlugin` и добавляется в список.

**Что делает `Task7`:**
1. Для каждого плагина печатает атрибут класса и описания методов из `PluginMethodAttribute`, пропуская методы `object` (`DeclaringType == typeof(object)`). Затем вызывает `Execute()`.
2. Находит `Calculator` по имени и вызывает `Add(10.0, 2.5)` через `ExecutePluginMethod`: `GetMethod("Add")` + `Invoke` → `12,5`.
3. Вызывает `Subtract` через обобщённую версию `ExecutePluginMethod<double>`. Она проверяет `method.ReturnType == typeof(T)` и приводит результат к `double` → `7,5`.
4. Проверяет `logger is IParameterizedPlugin` и вызывает `ExecuteWithParams` со словарём `message` → `[LOG] Плагин вызван с параметрами`.

**Смысл:** программа работает с плагинами, ничего не зная об их классах на этапе компиляции. Достаточно положить DLL в `Plugins` или дописать имя типа в `plugins.config`. Это **позднее связывание** и основа расширяемых приложений.
## 4. Теория кратко

### Метаданные и сборка
- **Сборка (assembly)** — единица развёртывания .NET: `.exe` или `.dll`. Содержит IL-код, метаданные типов, манифест (имя, версия, зависимости) и ресурсы.
- **Метаданные** — таблицы с описанием всех типов, полей, методов, параметров и атрибутов. Именно их читает рефлексия.

### Три способа получить `Type`
| Способ | Когда |
|---|---|
| `typeof(ReflectionTarget)` | Тип известен при компиляции |
| `obj.GetType()` | Есть объект, тип точный, даже если переменная объявлена базовым типом |
| `Type.GetType("LabReflection.DynamicCalculator")` | Есть только строка с полным именем; вернёт `null`, если тип не найден |

### Классы `System.Reflection`
| Класс | Что описывает | Главные методы |
|---|---|---|
| `Assembly` | Сборку | `Load`, `LoadFrom`, `GetExecutingAssembly`, `GetTypes` |
| `Type` | Тип | `GetMethods`, `GetFields`, `GetProperties`, `GetConstructors`, `GetInterfaces`, `IsAssignableFrom` |
| `MethodInfo` | Метод | `Invoke`, `GetParameters`, `ReturnType`, `CreateDelegate` |
| `FieldInfo` | Поле | `GetValue`, `SetValue` |
| `PropertyInfo` | Свойство | `GetValue`, `SetValue`, `CanRead`, `CanWrite` |
| `ConstructorInfo` | Конструктор | `Invoke` |
| `ParameterInfo` | Параметр | `Name`, `ParameterType` |
| `MemberInfo` | Общий предок всех `...Info` | `Name`, `DeclaringType`, `GetCustomAttributes` |

### `BindingFlags`
Флаги говорят, какие члены искать. Их комбинируют через `|`.
- `Public` / `NonPublic` — уровень доступа;
- `Instance` / `Static` — члены экземпляра или статические;
- `DeclaredOnly` — без унаследованных.

**Правило:** если флаги переданы, нужно указать и доступ, и `Instance`/`Static`, иначе результат будет пустым. Без флагов ищутся только `Public | Instance | Static`.

### Создание объектов
- `Activator.CreateInstance(type)` — конструктор без параметров;
- `Activator.CreateInstance(type, args)` — подбирает конструктор по аргументам;
- `type.GetConstructor(Type[]).Invoke(object[])` — явный выбор конструктора.

### Атрибуты
- **Атрибут** — класс-наследник `Attribute`, который добавляет к коду метаданные. Сам по себе ничего не делает, его читает другой код через рефлексию.
- `[AttributeUsage(AttributeTargets.Class)]` ограничивает, к чему можно применять атрибут.
- Суффикс `Attribute` при использовании можно опускать: `[Plugin(...)]` = `[PluginAttribute(...)]`.
- Чтение: `type.GetCustomAttribute<T>()`, `method.GetCustomAttribute<T>()`.
- Встроенные примеры: `[Obsolete]`, `[Serializable]`, `[Test]`, `[Required]`.

### Раннее и позднее связывание
- **Раннее:** вызываемый метод известен при компиляции (`calc.Add(1, 2)`). Проверяется компилятором, работает быстро.
- **Позднее:** метод находится во время выполнения по имени (`GetMethod("Add").Invoke(...)`). Гибко, но медленно, и ошибки видны только при запуске.

### Плюсы и минусы рефлексии
**Плюсы:** плагины и расширяемость, сериализация (JSON), ORM (Entity Framework), внедрение зависимостей (DI), тестовые фреймворки, отладчики и инспекторы.

**Минусы:**
- **медленно**: поиск по строке, проверки, упаковка аргументов;
- **нет проверки при компиляции**: опечатка в имени метода обнаружится только при запуске;
- **нарушает инкапсуляцию** и связывает код с приватной реализацией, которая может поменяться;
- **проблемы при обрезке кода** (trimming) и AOT-компиляции: компилятор не видит, какие члены нужны.

**Как ускорить:** кэшировать `MethodInfo`, создавать делегаты через `CreateDelegate`, использовать деревья выражений или генерацию кода.

### Исключения рефлексии
| Исключение | Когда |
|---|---|
| `MissingFieldException`, `MissingMethodException` | Член не найден (при вызове по имени) |
| `FieldAccessException`, `MethodAccessException` | Нет доступа к члену |
| `TargetInvocationException` | Сам вызванный метод бросил исключение; оригинальное лежит в `InnerException` |
| `ArgumentException` | Неподходящие типы аргументов |
| `TargetParameterCountException` | Неверное число аргументов |
| `ReflectionTypeLoadException` | `GetTypes()` не смог загрузить часть типов сборки |

## 5. Возможные вопросы на защите

**Что такое рефлексия?** Механизм получения информации о типах во время выполнения и работы с ними: создание объектов, вызов методов, доступ к полям.

**Откуда рефлексия берёт информацию?** Из метаданных сборки, которые компилятор записывает рядом с IL-кодом.

**Чем `typeof` отличается от `GetType()`?** `typeof` берёт тип, известный при компиляции, и вызывается на имени типа. `GetType()` вызывается у объекта и возвращает его реальный тип во время выполнения.

**Почему `GetMethods()` вернул 11, а не 1?** Он возвращает и аксессоры свойств (`get_`/`set_`), и методы, унаследованные от `object`.

**Как получить приватный метод или поле?** Передать `BindingFlags.NonPublic | BindingFlags.Instance` (или `Static`).

**Можно ли изменить приватное поле?** Да, через `FieldInfo.SetValue`. Модификатор доступа проверяется компилятором, а рефлексия обходит эту проверку.

**Чем `Invoke` хуже делегата?** `Invoke` каждый раз проверяет аргументы и упаковывает их в `object[]`. Делегат создаётся один раз и вызывается быстро.

**Что такое атрибут и как его прочитать?** Класс-наследник `Attribute`, добавляющий метаданные. Читается через `GetCustomAttribute<T>()`.

**Как `PluginManager` понимает, что тип — плагин?** Есть атрибут `PluginAttribute`, тип реализует `IPlugin` и это не интерфейс и не абстрактный класс.

**Что делает `IsAssignableFrom`?** `typeof(IPlugin).IsAssignableFrom(type)` истинно, если объект `type` можно присвоить переменной `IPlugin`, то есть тип реализует интерфейс.

**Чем `Assembly.Load` отличается от `LoadFrom`?** `Load` загружает сборку по имени (ищет в стандартных местах), `LoadFrom` — по пути к файлу.

**Что такое позднее связывание?** Выбор вызываемого метода во время выполнения, а не при компиляции.

**Где рефлексия применяется на практике?** Сериализация, ORM, DI-контейнеры, тестовые фреймворки, плагины, отладчики.

**Какие недостатки?** Медленно, нет проверки компилятором, нарушает инкапсуляцию, мешает обрезке кода и AOT.
